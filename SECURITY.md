# Security policy — preparation stage

No public release or supported version exists yet. Do not deploy this workspace for real student data until the release blockers in the readiness report are resolved.

A private reporting address has NOT been established. The owner must confirm and test a monitored private email address or enable GitHub private vulnerability reporting on the eventual repository before publication. Do not submit vulnerability details in public issues. If you already have a verified private contact with the maintainer, ask that contact for the secure reporting channel without sending student data or secrets.

A report should include affected version, minimal synthetic reproduction, impact, and suggested mitigation. Never include production credentials, real learner records, or recordings. Maintainers should acknowledge privately, reproduce in an isolated environment, coordinate a fix and advisory, and agree disclosure timing with the reporter. Response targets and supported versions remain to be assigned; none are promised here.
